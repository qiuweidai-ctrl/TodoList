# Deployment guide (Practicals 15–17)

Every environment-specific value in this project is a configuration setting, so deploying
**does not require editing any code** — only setting environment variables.
The steps below follow the practicals in order, and each one includes a way to verify it.

Reminder of the layout:

```
TodoList/
├── backend/     -> deployed to PythonAnywhere
└── frontend/    -> deployed to Netlify
```

---

## Practical 15 — Backend cleanup (PythonAnywhere)

### 15.1 Create a production superuser

Web tab → **Bash console**:

```bash
source .virtualenvs/todo_venv/bin/activate
cd ~/TodoList/backend        # your real path, the folder that contains manage.py
python manage.py createsuperuser
```

Write down the username, email and password (used to log into the admin panel).

> Note: the local `db.sqlite3` is not uploaded (it is listed in `.gitignore`),
> so production starts with an **empty database**. Run `migrate` before
> `createsuperuser`:
>
> ```bash
> python manage.py migrate
> ```

### 15.2 Check `.gitignore`

Already configured to cover the three categories the practical asks for:

| Rule | Purpose |
| --- | --- |
| `__pycache__/`, `*.py[cod]` | bytecode generated by Django |
| `backend/db.sqlite3` | local database, must never reach production |
| `.DS_Store`, `Thumbs.db` | OS metadata files |
| `todo_venv/`, `.idea/`, `.env` | virtualenv, IDE settings, secrets |

### 15.3 Switching databases (optional)

Free accounts can only use MySQL (PostgreSQL needs a paid plan). After creating the
database, put the connection settings in the environment variables on the Web tab
(or in the WSGI file) and update `DATABASES` in `backend/settings.py`.
A new database is empty, so you must run both commands again:

```bash
python manage.py migrate
python manage.py createsuperuser
```

For a course demo, staying on SQLite is perfectly fine.

### 15.4 CORS comes last

The CORS whitelist needs the **live frontend URL**, so finish Practical 16 first and
come back to it (see section 17 below).

## Practical 16 — Deploy the frontend (Netlify)

### 16.1 Point the frontend at the live backend

The practical suggests editing the `localhost:8000` URLs in `services/todos.js` by hand.
This project does the equivalent with an environment variable (the code already reads
`process.env.REACT_APP_API_URL`):

```bash
cd frontend
# PowerShell
$env:REACT_APP_API_URL="https://yourname.pythonanywhere.com/api"

# macOS / Linux
export REACT_APP_API_URL="https://yourname.pythonanywhere.com/api"
```

Alternatively copy `frontend/.env.production.example` to `frontend/.env.production` and
fill it in; `npm run build` picks it up automatically (that file is not committed).

### 16.2 Build

```bash
npm run build
```

The output is written to `frontend/build/`.

### 16.3 Upload to Netlify

1. Open <https://app.netlify.com/drop> (or use the drop zone in the project page)
2. Drag the **`build` folder itself** into the upload area
3. After a few seconds you get a URL such as `https://random-name-123456.netlify.app`

### 16.4 Make the site public

Netlify's newer UI creates projects with **Private** visibility, which returns
`401 Login Redirect` for anybody who is not a team member. To open it up:

> Project → **Project configuration** → **General** → **Visitor access** →
> **Project visibility** → **Edit visibility** → set *Production visibility* to **Public**

Leave *Deploy Preview visibility* on Private; it only affects preview URLs.

### 16.5 Why `_redirects` is needed

`frontend/public/_redirects` contains `/*  /index.html  200`. It exists for React Router:
opening `https://your-site.netlify.app/login` directly has no matching file on the server,
so without that rule Netlify returns 404. CRA copies the file into `build/`, so
drag-and-drop deployments get it automatically.

## Practical 17 — Connect the two halves (CORS)

Once you have the Netlify URL, go back to the PythonAnywhere **Web** tab and add it to
the environment variables (or to the WSGI file):

```
DJANGO_CORS_ORIGINS = https://your-site.netlify.app
```

If other origins are already listed, separate them with commas:

```
DJANGO_CORS_ORIGINS = https://your-site.netlify.app,http://localhost:3000
```

Also confirm these three:

| Variable | Value |
| --- | --- |
| `DJANGO_DEBUG` | `False` |
| `DJANGO_ALLOWED_HOSTS` | `yourname.pythonanywhere.com` |
| `DJANGO_SECRET_KEY` | a long random string |

Then press **Reload**.

### Verify

1. Open the Netlify site and sign up — you should land on the todo list
2. Add, edit, complete and delete a todo
3. Log in with an older account and check that previous tasks are still there

If it still fails, work through this table:

| Symptom | Cause | Fix |
| --- | --- | --- |
| `CORS policy` error in the console | origin missing from `DJANGO_CORS_ORIGINS`, or a trailing slash | use scheme + host only, **no trailing `/`** |
| "cannot reach the backend" alert | `REACT_APP_API_URL` was not set when building | rebuild and upload again |
| Page returns 404 | `_redirects` missing | check that `build/_redirects` exists |
| 502 / endless spinner | WSGI error after Reload | check the error log on the Web tab, usually `ALLOWED_HOSTS` |
| `401 Login Redirect` for other people | project visibility is Private | set *Production visibility* to Public |

## Appendix — the WSGI file used in this deployment

`deploy/pythonanywhere_wsgi.py` is the template actually used. It injects the
configuration through `os.environ` so `settings.py` stays untouched:

```python
import os
import sys

project_home = "/home/qiuweidai/TodoList/backend"
if project_home not in sys.path:
    sys.path.insert(0, project_home)

os.environ["DJANGO_SETTINGS_MODULE"] = "backend.settings"
os.environ["DJANGO_SECRET_KEY"] = "a generated random key"
os.environ["DJANGO_DEBUG"] = "False"
os.environ["DJANGO_ALLOWED_HOSTS"] = "qiuweidai.pythonanywhere.com"
os.environ["DJANGO_CORS_ORIGINS"] = "https://your-site.netlify.app"

from django.core.wsgi import get_wsgi_application

application = get_wsgi_application()
```
